# IncidentLens v0.1.0: release notes

First public release of IncidentLens, a portfolio project that turns raw application logs into a structured
incident report. **The analysis is deterministic, rule-based and runs entirely in-process. No LLM is called,
no API keys are needed, and nothing is stored.** An `llm.py` extension point exists for a possible future,
optional enrichment layer; it is not wired to any model.

## Highlights

- **Ingestion:** plaintext, JSON array and JSONL with auto-detection; drag-and-drop or manual entry; malformed
  records are counted and skipped; size and record limits (413 for over-limit input, including chunked uploads).
- **Redaction before analysis:** API keys, tokens, passwords (including JSON-escaped, single/double-quoted and
  unterminated values), JWTs, emails, URL credentials, `Authorization` headers and PEM private keys.
  Best-effort pattern matching, not a guarantee (see `docs/SECURITY.md`).
- **Deterministic analysis:** error grouping, severity distribution, spike and cascade detection, lagged
  cross-service correlation, and seven hypothesis rules with transparent heuristic scores (not probabilities).
  "No incident" and "insufficient evidence" are first-class outcomes.
- **Dashboard:** dark, responsive, with timeline, charts, ranked hypotheses with evidence, filterable log viewer,
  investigation steps, and Markdown/JSON export.
- **Seven synthetic scenarios** with machine-checked expected outcomes (`docs/DEMO_SCENARIOS.md`).
- **Static demonstration build** for GitHub Pages: fixtures are generated by the Python engine at build time;
  uploads and manual analysis are disabled; no backend is exposed.

## Quality gates (verified in GitHub Actions)

- Backend: pytest on Python 3.11 and 3.13, demo-scenario evaluation, demo-data sync check, benchmark smoke test.
- Frontend: strict TypeScript, Vitest, production build (`npm ci` with a committed lockfile).
- Real-browser smoke tests (Playwright, Chromium, desktop and mobile viewports) on the static build, asserting charts
  render, filters work, reports download, no backend requests and no console errors.
- Docker Compose build plus an HTTP smoke test of the running stack.

Exact counts are in the README ("Verified quality").

## Security hardening since the first MVP

Sanitized 422 responses (no input echo); clipping that cannot leave half a secret behind; multi-line private keys;
NaN/infinity/huge numeric severities handled; bounded memory for high-cardinality services; Markdown table
injection fixed; chunked oversized uploads answer 413; escaped and unterminated quoted secrets redacted.
Each has a regression test.

## Known limitations

See `docs/LIMITATIONS.md` and `docs/SECURITY.md`. In short: heuristic analysis tuned on synthetic data only;
pattern-based redaction misses secrets with no recognizable shape; no authentication, so do not expose the full
application to the public internet; plaintext parsing covers common shapes only.

## Release blockers (owner decisions)

- **License:** none included. Choosing one (MIT was suggested) requires explicit owner authorization.
- **Merge and GitHub Pages:** the deployment workflow only runs after CI succeeds on `main`, and the Pages source
  must be set to "GitHub Actions" in repository settings. Nothing is deployed until then.
- **Dependency audit:** see "Dependency audit" in `docs/SECURITY.md`.
